Which retrieval settings find the true value?

Truth coverage and graded relevance of the documents medsim retrieves (Europe PMC + LitSense), on the 141 set A questions of the retrieval benchmark · judge anthropic/claude-haiku-5.5 · 37 scored configurations and controls

Result. The best configuration is llm_select20+epmc25+q_synonym (an LLM picks the 8 documents from the best 20; 25 Europe PMC candidates (baseline 50); Europe PMC MeSH synonym expansion): strict truth coverage 70.2% against the baseline's 60.3% (+9.9 (+3.5 to +17.0) points, paired over the same questions), nDCG@8 0.750 against 0.691, and precision@8 49.6% against 41.3%. On fresh queries: query set fresh1: strict +7.1 points, nDCG +0.054; query set fresh2: strict +12.1 points, nDCG +0.058.

What was measured

  • Strict truth coverage (decides): a document gives a value or range for this variable in patients with this or a closely related condition, and the hidden true value lies inside it or within about 15%. Category coverage (shown): a document's value, range, or level, a reference range for comparable patients included, puts the true value in the same low / normal / high category.
  • Graded relevance: each document 0 (not about the variable or the condition), 1 (about them, no usable value), or 2 (a value for the variable in comparable patients). nDCG@8 is against a perfect list of eight grade-2 documents, so it rewards better documents and a better order (it breaks ties); precision@8 is the share of grade-2 documents.
  • One judge call per question grades all eight documents and gives both coverage verdicts. Every positive verdict needs a verbatim quote that code finds in the named document; an unverified grade 2 counts as 1, and unverified coverage as not covered.
  • Each configuration retrieves for the same frozen search query per question (medsim's Stages A and B once, with the stored runs' model deepseek/deepseek-v4-flash-0731), and no answer is written. Differences between configurations therefore come from the retrieval settings. Eight documents per question throughout. Search results are cached, so a configuration that issues the same requests gets the same results.

Cost and limits

  • Cost of this work from the stored usage records: $9.11 (judge $7.00, LLM selection during retrieval $1.79, query writing $0.32). Europe PMC and LitSense are free.
  • One judge, an LLM, without human labels: absolute levels may be off; the comparisons between configurations, made by the same judge on the same questions, are the point.
  • 141 questions: differences of a few points are inside the noise.
  • Europe PMC answered HTTP 503 during the first retrieval of the two fresh-query baseline runs (129 and 64 of 141 questions lost it). Those questions were retrieved again once it recovered and judged again; the tables use the second attempt. Every other run had no failed source.
  • LLM selection adds one call per question to medsim's retrieval (about $0.0016 with deepseek/deepseek-v4-flash-0731, and its latency). It is not medsim's default yet.
  • The best configuration was chosen on these questions; the fresh-query runs re-test it, but on the same 141 questions, not on new ones.
