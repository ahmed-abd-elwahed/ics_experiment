New answer metrics for the simulated environment

Information Collection Strategies Experiment · environment benchmark · 13 October 2026

What was asked. The two existing answer metrics (masked correctness and factual consistency) barely separate the retrieval methods. The task was to add metrics that separate them more, test each on one run with one judge, revise once if needed, then score all ten stored runs with the whole judge panel, with the Jev decision model as an added judge.
  • Faithfulness separates every pair of retrieval methods. Its spread between methods is 8.1 times its run-to-run noise; for the two old metrics the ratio is 0.2 to 0.7. The documents support 59% of Perplexity's answers, 35% with retrieval changes 1–4, and 21–25% for the other three methods.
  • The zlog z-score does not separate the methods (ratio 0.5–0.6, like masked correctness). The methods' answers are equally close to the true value; Gemini without any search is as close as the search methods.
  • Case alignment separates them slightly (ratio 1.0–1.4): answers from Gemini's own knowledge and from Perplexity are contradicted by the case a little more often (about 3% against 1.5%). The differences are one to two points.
  • The old metrics hardly moved under the new panel (Claude Haiku 5.5 and GLM 5.3 Flash in place of Gemini and Qwen): same category 83–86%, consistent about 97%, as before.
  • Adding Jev as a fourth judge changes little: most scores stay within one point. Exact masked correctness falls by one to two points, and native Google search's faithfulness by three (23.5% to 20.6%, one run).
  • One part is incomplete. Faithfulness and case alignment by the three chat judges cover nine runs, not ten: the API key reached its total spending limit of $250 during run 10. Everything else covers all ten runs.

What the scores show

  • Retrieval changes what an answer rests on, not how right it is. Faithfulness ranges from 21% to 59%, while every closeness measure is flat: same category 83–86%, mean |z| 1.25–1.32.
  • Changes 1–4 do what they were built for. They raise supported answers from 22.7% to 35.1% for the same sources, although masked correctness did not change.
  • Perplexity is the most grounded and Exa instant the least (59.2% against 21.0%). Native OpenAI search reaches 38.3% and native Google search 23.5%, each on one run.
  • The judges confirm less support than the environment claims. It labels 61% of Perplexity's answers, 47% with changes 1–4, and about 30% of the others as taken from the documents; the judges confirm 59%, 35%, and 21–25%.
  • Case alignment: about one answer in five is aligned with something the case says and 1–3% are contradicted, for every retrieval method. The rest are neutral: the case gives no expectation for the variable.
  • Set C behaves as it should. When the case states the answer, mean |z| is 0.04 and 97.7% of answers are aligned.
  • Empty cells: faithfulness has no value for Gemini knowledge and for case study only, which retrieve no documents.

Why the old metrics separate the methods poorly

  • Coarse labels. Masked correctness has four labels and factual consistency two. Turning a continuous outcome into categories loses at least a third of its statistical information [1, 2].
  • A ceiling. About 97% of set B answers are consistent, for every method.
  • They never look at the retrieved documents. When the documents are weak, the synthesizer answers from its own knowledge and still lands in the right category.

Zlog z-score: the equations

zlog(x) = (ln x − (ln LL + ln UL)/2) · 3.92 / (ln UL − ln LL)     [3], LL and UL: lower and upper reference limits z = zlog(answer) − zlog(truth) = (ln answer − ln truth) / σ,   σ = (ln UL − ln LL) / 3.92     [4], the true value as the assigned value revised (kept): σ is multiplied by max(1, |zlog(truth)| / 3.92)

The answer's error is measured in units of the healthy population's spread. ISO 13528 rates |z| ≤ 2 satisfactory and |z| ≥ 3 unsatisfactory. Rules beyond the two methods, all this project's choices: a one-sided reference range takes a lower limit of 15% of the upper; a variable without a reference interval takes σ = 0.15; values at or below zero use the same z without logarithms; for blood pressure the systolic value is scored; a true value given as a range or bound scores 0 for an answer inside it.

  • Faithfulness was kept as designed: about ten times the old metrics' ratio.
  • Zlog z-score, one revision. 22% of scores sat at the cap, many for very abnormal true values answered with similarly abnormal ones (haemoglobin 4 g/dL answered as 6.8). The revised scale widens the tolerance with the true value's own distance from normal. It was kept (0.25 against 0.23), a difference well inside the noise.
  • Case alignment, one revision. The first version asked for one verdict and counted only explicit statements: 96% of answers came back neutral and none contradicted. The revised version lets the clinical picture set an expectation and compares two levels. It was kept (0.60 against 0.57), again inside the noise, but it uses the scale: 16–19% aligned, 2–4% contradicted.
  • Neither revision made its metric more sensitive than the old ones on this run. The nine-run figures below show the same for the zlog z-score and a modest gain for case alignment.

The judges

  • Panel: Claude Haiku 5.5 (main judge, breaks ties), GLM 5.3 Flash, and GPT-6 Luna. Haiku replaced Gemini 3.5 Flash Lite and GLM replaced Qwen 3.8 Flash, in the old scores as well: both re-judged every answer of the ten runs. GLM was chosen from four candidates on 40 stored answers.
  • Jev 1.13 is a decision model: it returns a choice with probabilities and no text. It judged both old metrics, faithfulness, and case alignment for all ten runs. It cannot read out a number, so the zlog z-score has three judges in both tables, and its verdicts cannot be quote-checked.
  • Agreement on faithfulness (18,904 answers): the three judges are unanimous on 75.5%; any two agree on 81–85%, and Jev agrees with each of them as often (81–85%).
  • Agreement on case alignment (14,823 answers): the three judges are unanimous on 79.3% and agree pairwise on 84–88%. Jev agrees with them on only 60–67%: it calls 53% of answers aligned, the others 17–27%. With three other votes it rarely decides the label.
  • Batch API: not used. Gemini's batch endpoint is refused under the account's data-retention setting, and two GPT batches had completed nothing after 25 minutes.
  • Volume and cost: about 289,000 judgments, whose recorded cost is $49.46; with tests and calibration, about $50. The key's usage that day was $56.60, which also covers another experiment run on the same key.

Limits

  • Nine runs, not ten, for two metrics. The API key's total limit of $250 was reached during run 10, so the three chat judges' faithfulness and case alignment for that run are unfinished and left out. Jev's verdicts for run 10 exist but are not shown alone.
  • Faithfulness rewards grounding, not truth. An answer can be faithful to a document that is wrong for this patient, and a method that returns more text has more chances of containing an agreeing number.
  • The planned sanity check for faithfulness was not run (another question's documents should give "not supported"); the key limit was reached first.
  • The versions were chosen on one run and one judge, on differences smaller than the noise.
  • The reference limits come from the judges, as the median of three; 103 of the 140 set A questions have a two-sided interval, 15 a one-sided one, 22 none.
  • The revised zlog scale and the special-case rules are this project's own, not from the cited methods.
  • All judges are language models. No human labels were collected for the new metrics.
  • Native Google and OpenAI search have one run each, so no standard deviation.
