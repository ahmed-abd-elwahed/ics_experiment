What all four share

Kept from the current code

  • Each strategy is a StrategySession subclass registered in strategies.STRATEGIES. next_question() returns a Question, or None to stop (the runner already records this as strategy_done).
  • Every LLM call goes through call_structured with a pydantic model, so replies are validated and each call lands in the record with its tokens and cost.
  • The strategy sees only output_answer. max_iterations stays as a ceiling for every strategy.

New for all four

  • A diagnosis step. Every slide ends in "Return diagnosis", but the runner never asks a strategy for one. I would add final_diagnosis() to the session, called after any stop, including a forced stop at max_iterations.
  • Grading. A judge compares that diagnosis with the case's hidden one. The research question asks for the most accurate strategy, so this is the outcome measure.
  • The LLM estimates, code decides. The model returns numbers or labels; the stop rule is a plain comparison against thresholds in the strategy's params. The thresholds can then be tuned and reported.

1. Hypothesis-driven search

Slide 8: Collect new information → Update your hypothesis → Satisficing hypothesis? → No: collect again · Yes: return diagnosis

Proposal

  • The session keeps a ranked differential. After each answer one LLM call rewrites it, with a probability and the evidence for and against each diagnosis.
  • A second call picks the question whose answer would most change the ranking, and names the diagnoses it separates.
  • "Satisficing" becomes: the leader's probability is at least accept and it leads the runner-up by at least margin.
  • The diagnosis is the top of the differential, with no extra LLM call.

Sketch

class HypothesisSession(StrategySession):
    def next_question(self) -> Question | None:
        if self.memory:  # nothing to update before the first answer
            self.differential = self.call(UPDATE, Differential)
            top, second = self.differential.ranked()[:2]
            if top.p >= self.p.accept and top.p - second.p >= self.p.margin:
                return None          # satisficing hypothesis
        turn = self.call(ASK, SplittingQuestion)
        return Question(turn.question, turn.rationale)

    def final_diagnosis(self) -> Diagnosis:
        return Diagnosis(self.differential.ranked()[0].name)

2. Knowledge-driven search

Slide 9: Collect new information → Recognize patterns → Satisficing information? → No: collect again · Yes: return diagnosis

Proposal

  • Questions are driven by gaps in the data, never by a candidate diagnosis. The prompts forbid naming a diagnosis until the last step, which is what separates this from strategy 1.
  • After each answer a "recognise patterns" call groups the findings into syndromes (for example "febrile illness with a new murmur") and lists the key findings each pattern still lacks.
  • "Satisficing information" becomes: one pattern has no key finding missing, and the basic history, examination and vitals are covered.
  • Only then does an LLM call match the completed pattern to a diagnosis.

Sketch

class KnowledgeSession(StrategySession):
    def next_question(self) -> Question | None:
        if self.memory:
            self.picture = self.call(RECOGNISE, ClinicalPicture)
            complete = [p for p in self.picture.patterns if not p.missing]
            if complete and self.picture.basics_covered:
                return None          # satisficing information
        turn = self.call(ASK_MISSING, GapQuestion)  # reads picture.missing
        return Question(turn.question, turn.rationale)

    def final_diagnosis(self) -> Diagnosis:
        return self.call(MATCH, Diagnosis)  # first time a diagnosis is named

3. Channel-based

Slide 11: Conduct patient interview → Confident in diagnosis? → Yes: return diagnosis · No: physical exam

Proposal

  • A channel is a kind of source. The session works through an ordered list, ["interview", "exam"], and each channel has its own prompt and its own question cap.
  • The environment answers anything, so the restriction has to sit on the strategy's side. A short classifier call labels each question; code rejects one that falls outside the current channel and asks for another.
  • Confidence is checked once per channel, when the channel is used up, not after every answer. That matches the slide, where the check follows the whole interview.
  • The slide draws no arrow out of "Physical exam". I would check confidence again and return the diagnosis either way, because no channel is left.

Sketch

class ChannelSession(StrategySession):
    def next_question(self) -> Question | None:
        while True:
            if self.channel_done():      # cap reached, or the LLM had nothing left
                self.view = self.call(ASSESS, DiagnosisWithConfidence)
                last = self.channel == self.p.channels[-1]
                if self.view.confidence >= self.p.confident or last:
                    return None
                self.channel = self.next_channel()
            turn = self.call(ASK[self.channel], ChannelQuestion)
            if turn.nothing_left:
                self.exhausted = True; continue
            if self.classify(turn.question) == self.channel:   # else re-ask
                return Question(turn.question, turn.rationale)

    def final_diagnosis(self) -> Diagnosis:
        return self.view.diagnosis

4. Sequence-based

Slide 12: Initialization of diagnosis → Refinement of diagnosis → Defining the final diagnosis

Proposal

  • Three phases in a fixed order, each with its own prompt and goal. Unlike the other three, there is no early exit: every run passes through all three.
  • Initialization: a few open questions, then one call drafts a differential of at most five diagnoses.
  • Refinement: each question aims to remove a candidate; after each answer the list is pruned or reordered.
  • Final diagnosis: ask for the finding that would confirm or exclude the leader, then commit.
  • Code moves between phases on the list's length or on each phase's share of the question budget.

Sketch

class SequenceSession(StrategySession):
    def next_question(self) -> Question | None:
        n = len(self.memory)
        if self.phase == "init":
            if n >= self.p.opening:
                self.candidates = self.call(DRAFT, Candidates)
                self.phase = "refine"
        elif self.phase == "refine":
            self.candidates = self.call(PRUNE, Candidates)
            if len(self.candidates) <= 2 or n >= self.refine_until:
                self.phase = "final"
        else:
            self.verdict = self.call(SETTLE, Verdict)
            if self.verdict.settled:
                return None
        turn = self.call(ASK[self.phase], PhaseQuestion)
        return Question(turn.question, turn.rationale)

Open questions for you

  1. Channel-based: are tests a channel? The slide has only the interview and the physical exam. With only those two, this strategy can never ask for a lab result or imaging, while the other four can. Either add a third channel, or accept that as part of what the strategy is.
  2. Channel-based: what follows the physical exam? The slide draws no arrow out of it. I assumed a second confidence check, then the diagnosis.
  3. Sequence-based: when does a phase end? The slide gives the order but no conditions. I assumed 3 opening questions, refinement until 2 candidates remain or 75% of the budget is used, then the final phase.
  4. Thresholds need a pilot. A probability or confidence that an LLM states is not calibrated. I would run a few cases, look at where each strategy stops, and set the thresholds before the real run.
  5. Reporting. The strategies stop after different numbers of questions, so accuracy should be reported next to questions asked and cost. All four should use the same model and the same max_iterations.
